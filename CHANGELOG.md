# Changelog

Notable product changes in Rakazo. See GitHub Releases for tagged builds.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Fixed

- Resuming after a long pause cancelled work that was waiting on the user's open cards, and queued work the pause had held, as "stuck". A run waiting on an open card now never expires, and time spent paused no longer counts towards expiry.
- The approval to send a Zendesk reply showed the customer context as unavailable, because the Fleet now sends it in a new shape. The review shows the customer's full inquiry again and says when a newer customer message arrived since the approved version.
- A to-do's release message was hidden when its automatic check verified it, because it was filed under the hidden check run; it now shows in the chat like a manual confirmation. A withdrawn or ended card no longer previews in the sidebar as its question, but as "No longer needed".
- Answering a card with the to-do option showed its to-dos only after up to a minute; the To-dos panel and the card's checklist now update at once.
- After resuming, Fleet work stayed in "Needs attention" when the Fleet's safety check took longer than 30 seconds. The check now has 90 seconds, and a run it could not check is retried automatically every 5 minutes for a day. The Fleet control dialog now fits the screen at normal zoom: its buttons stay visible and the attention list is folded under a count, each code with a plain explanation.
- A Fleet run held because the Fleet could not confirm its job link waited for you with nothing to click. Unfinished operations now offer "Check again", "Let it continue" (once, past the Fleet's check, recorded as your override) and "Stop it", all recorded; a run whose job link the Fleet could not find is also checked again hourly for a day, so a fix on the Fleet side releases it by itself. Needs migrations `20261023120000_maintenance_recovery_run_actions` and `20261023130000_maintenance_recovery_recheck`.
- A run the Fleet held (its room, case or job changed) was re-checked with the Fleet every 30 seconds, indefinitely. Such holds are now checked hourly for a day, explained in plain words, and can be stopped; a run waiting on your card answer is checked every 5 minutes.
- A run could stay stuck forever behind an action that was cut off by a restart: the run could not start until the action settled, and only the run could settle it. Such an action is now marked uncertain after 10 minutes and Unfinished operations asks you what happened; "it did not take effect" has it done again when the run resumes. Any run held for attention can now be stopped from the list, a run the Fleet says is no longer needed is cancelled automatically, and a run held because something changed says what changed and is checked again hourly. Needs migration `20261023140000_maintenance_recovery_fleet_obsolete`.
- A retired approval card read "No longer needed" twice. It now shows the phrase once, followed by the reason, on web, mobile and in the sidebar.
- An approval that ended because its question was withdrawn or stopped kept Fleet control in "Needs attention", held paused work from resuming, and could not be cleared from Unfinished operations. Such approvals now count as finished everywhere.
- A bot retiring the last open to-do of a card was told to "continue the work" by a release message, even when the case had ended. Retiring a to-do now wakes nothing; the bot decides itself.
- "Done – check now" on a to-do started an ordinary chat run with every tool. It now starts the same short, read-only check as the hourly sweep, run by the case coordinator, and during a pause it waits until resume.
- A card whose run had ended (stopped, withdrawn, cancelled, failed or completed) stayed "pending" forever, and withdrawing such a card did nothing. Cards now end with their run: an unanswered card is marked no longer needed, with "Withdrawn: <reason>" or "Its run ended without an answer", and open tabs refresh. Cards already left open are cleaned up automatically, and withdrawing one now retires it.
- A to-do was tied to its case only by the words of its card ("Case 383 · …"), so cancelling the case left its to-dos open. To-dos now carry their tracker case number; the To-dos panel links "Case <n>" to the issue, and the Fleet service can list a case's to-dos and retire the unfinished ones with a reason when the case ends (finished ones stay, nothing is deleted). Existing to-dos are linked only where their card started exactly with "Case <n> · ". Needs migration `20261022090000_user_todo_case_ref`.
- A to-do the bot can check waited for you to tick it, even after you had finished the step. Pending checkable to-dos are now checked once an hour by the bot that asked, in a short read-only check that sees only the to-do (not the conversation) and posts nothing in the chat; a finished step releases the waiting work without another click. Steps only you can confirm are never checked automatically. Ticking a to-do still checks it at once. Nothing is checked during a global pause.
- A reply card showed only the draft: the customer's inquiry was not on it, an older card for a conversation stayed answerable after the customer wrote again, and the buttons did not say who acts. Reply cards now show the full inquiry and the editable reply (long text folds behind "Show all", never cut) and are bound to the conversation version they answer; a newer version replaces the older open card with a reason. Every card says under its buttons who acts and what a click does. Editing a reply before answering sends one learning note to the feedback bot (Elena), which changes no approval. Old withdrawal approvals whose question already ended are now retired without waiting for a click.
- Choosing "I'll do it myself" on a question card was only an answer: nothing tracked the manual steps, so a promise to change access could be mistaken for done, or asked again. A card can now list the manual steps (`ask_user` `prerequisites`, `option`, `release`); choosing that option gives you one to-do per step, grouped by the card, under To-dos in the sidebar, and on the answered card itself. Each item is one line with a checkbox: ticking it means "I did this", with 5 seconds to undo. The bot then verifies it with its own read-only tools (ticked when verified, or unticked again with "still missing: …" or "couldn't check"); a step only you can confirm is ticked at once, marked "(you)". Steps open on click; finished items fold into "Done (N)". Asking again about the same requirement keeps the same to-do and its progress. The bot continues once each item, or all of them, are satisfied, through a normal message, so a paused fleet stays paused and nothing is approved by it. Needs migration `20261021200000_user_todos`.
- Queued bots no longer display the transcript's actively-working indicator, including requests retained during a global Fleet pause.
- Bot avatars (sidebar, chat header, rooms and the mobile inbox) no longer play the working animation while a bot is queued, waiting for your answer or takeover, or paused for maintenance. Only a claimed or running turn animates; those runs still show their Waiting in line, Needs your answer or Paused status.
- Fleet control now lists every unfinished operation behind Pausing or Needs attention (run, attempt, effect, Fleet effect), with its bot, run, start time and evidence. When the run's own records decide the outcome, **Record as …** applies it; otherwise the missing evidence is named and the owner can record a checked outcome with a note. A terminal run or an expired lease alone never settles anything, a real outcome that lands first is kept, and every settlement is audited. Nothing is resumed, retried or undone.
- An approval card that depended on a question (for example "withdraw this question") no longer stays actionable after that question is answered, withdrawn or stopped. It is retired with a reason ("No longer needed: …") instead of an answer, disappears from the decision dock and the waiting counts in every open tab, and the bot's paused run continues with "this approval no longer applies". Clicking a card that was already answered or retired in an old tab now says that nothing was sent instead of silently dropping it.
- A Railway computer whose sandbox had been destroyed could not start again: it failed with "Railway live screen requires PRIVATE networking" instead of creating a new sandbox, because Railway no longer reports networking for a destroyed sandbox. It now starts a new sandbox and restores the portable home.
- The Amazon Bedrock model picker was missing newer models available on Bedrock: Claude Sonnet 5.5, GPT-6 Luna, GPT-6 Sol and GPT-6.1 Sol, Grok 4.7, Kimi K3, GLM-5.3, and the India (`in.`) Claude inference profiles. They are now listed with their regional and global inference profiles until the bundled provider library ships them.
- Fish Audio speech can use a model other than s2.1-pro. Each Fish connection can set Speech model in Voice settings; `FISH_TTS_MODEL` is the default only when that field is empty (unset still uses s2.1-pro). A failed speak, transcribe, or voice-list request logs the upstream Fish status and message, including when the error body cannot be read, and the message returned to the client does not include the API key.
- A picture attached to an earlier message is now visible to the bot when a later turn asks about it, for a model that can see images. Only the current turn carried its images; older turns arrived as a text marker, so the bot asked for the picture again. The most recent user turns now keep their images, within a fixed turn, byte, and per-model image budget. A turn whose pictures exceed the byte budget keeps the newest ones that fit. If an earlier picture cannot be read, its history marker says it is unavailable.
- A bot on a reasoning model could answer with "No response. Try again." on a harder question: thinking is billed against the same output ceiling as the reply, and the 4k default left nothing for the reply itself. Reasoning models now get a 32k output ceiling instead, still bounded by whatever the model itself allows.
- A newly created bot's thread opened empty and stayed silent until given real work, so a misread `title`/`description`/`instructions` went unnoticed until it cost a run. Creating a bot now queues one turn where it states how it understood its role and asks for anything it needs.
- A message sent while that introduction was still running was answered by the intro, which cannot use tools. The message now waits until the introduction finishes and is answered in the following turn, and the introduction does not send a finish notification. A reply to a message from a linked chat app still goes back to that app. Messages held from different chats, such as a group channel and a direct chat, are answered in separate turns.
- A message sent while one of the bot's routines (or an inbound webhook) was running in the same thread was folded into that turn as steering, so the bot answered without the conversation ("I have no earlier context"). The message now waits until that turn finishes and is answered in its own turn with the full thread. A composer reply while that run is already waiting for input still answers the ask, unless a live conversational run is active to take the message.
- Every turn failed on Claude models through Amazon Bedrock with "input_schema does not support oneOf, allOf, or anyOf at the top level": `request_secret` declares its two destinations as a root `oneOf`, and Anthropic rejects the whole request for it. Root unions in tool schemas, including ones from MCP servers, are now merged into a single object schema before they reach a provider; the executor still enforces credential or `connectionId`, not both.
- Pipedream exposed every tool of every connected app at once, so a handful of apps could fill a run's tool list. Above 20 tools the connector now offers the same lazy catalog the MCP connector uses (`pipedream_search_tools`, `pipedream_load_tool`, and `pipedream_execute_tool`), with names grouped by app.
- The Needs you computer card in a thread now includes Open, which opens that bot's computer the same way the computer panel does, including from a group member bot.
- Bots with more than 20 MCP tools failed on every Claude model behind a Claude Pro/Max/Team sign-in with "You're out of extra usage": Anthropic rejects Claude Code OAuth requests that carry a tool named `mcp_*`. The lazy catalog wrappers are now `connectors_search_tools`, `connectors_load_tool` and `connectors_execute_tool`.
- Changing a bot's model, thinking level or voice failed with a validation error once its instructions outgrew the description limit, and saving any other setting overwrote those instructions with the shorter description text. Bot settings now put the description and instructions on the wire only when that field was edited, clamped to each field's own limit.

### Changed

- Bots must give every to-do a reason, numbered steps and the tracker case it belongs to; a to-do request without them is refused with what to fix.
- A bot whose run the Fleet pause holds shows "Paused after N steps" in the sidebar, so the progress it kept is visible.
- Unfinished operations in Fleet control show the case, who follows up, and whether you need to act. A Fleet service operation says how to settle it in the Fleet service, and work a Fleet wake started shows its case from that wake, or "Case unknown".
- A card's to-do option says how many to-dos it adds and, when the bot gave one, about how long they take; the steps show after you choose. A check held by the Fleet pause says "waiting — Fleet paused", and an item you confirmed says "Confirmed by you".
- Message bubbles in the web/PWA transcript use more of a wide window's width (70%/74% caps raised to 84%/88%, still leaving room for the hover-actions gutter), instead of leaving a quarter to a third of a long message's row empty.
- Every run's system instructions now state the current date and time (UTC), so bots judge deadlines, recency and scheduling from the real present instead of guessing it from training data or quoted timestamps.
- Connect Slack, WhatsApp Business Cloud, or Telegram DMs to a bot from Messaging settings, alongside iMessage/SMS. Each app can use a different bot. Group conversations remain iMessage-only.
- Model picker includes Grok 4.6 (xAI) and Ox Alpha Free / GLM-5.3 (OpenCode Go).

### Added

- Deployment owners can gracefully pause the whole Fleet, resume it explicitly, or separately confirm force stop from the web header. Pause survives restart, retains incoming work and exact continuations, and reports active or uncertain effects rather than pretending they were undone. No bot is exempt. See [global graceful Fleet pause](docs/maintenance-admission.md) for coordinated rollout and recovery.
- Self-hosted deployments can run multiple Telegram bots, for example one per space, using `TELEGRAM_BOT_TOKEN_<NAME>` and `TELEGRAM_WEBHOOK_SECRET_TOKEN_<NAME>` pairs.
- Railway computers can start in a chosen region. Set `RAILWAY_SANDBOX_REGION` to keep them near the API instead of Railway's default region, so each command, click, and screenshot avoids a cross-region round trip. Unset, nothing changes.
- A ```mermaid block in a bot's message is drawn as a diagram, on the web, in the desktop app and on mobile, in the app's light or dark palette. Source Mermaid cannot draw stays a code block, and a block the bot is still writing reads as code until it is complete. On the web, Mermaid loads only when a message contains a diagram, and a diagram's source can be copied. The mobile app draws diagrams with Mermaid served by your own server (`/api/v1/assets/mermaid.js`), so an older server keeps showing code blocks.
- A routine can run on its own model and thinking level, picked in the routine editor. Left on the bot's model, nothing changes. A run keeps the model chosen when it was created, so editing the routine afterwards cannot move a waiting run, and a later resume does not treat the model an attempt recorded as that choice. Webhook, GitHub, and message deliveries use a routine model when every routine in that delivery chose the same one, including when the delivery has to wait for the bot to finish.
- The deployment-wide default model can run on Amazon Bedrock without a key. With `PI_DEFAULT_CREDENTIALS=host`, `PI_DEFAULT_PROVIDER=amazon-bedrock` and `PI_DEFAULT_MODEL` set, a deployment whose host has an AWS role (an ECS task, IRSA or EC2 instance role) counts as having a default model, and runs use those credentials instead of a stored Bedrock API key.
- Voice mode: spoken replies, hold-to-talk dictation, and half-duplex calls with ElevenLabs, OpenAI, Cartesia, or Fish Audio.
- Desktop owners using Docker can opt into running bot shell commands directly on their computer. This grants access under the owner's OS account; see [computer providers](docs/self-host.md#choosing-a-computer-provider).
- GitHub Copilot and SuperGrok / X Premium sign-in for model access.
- Spawn peer bots (each with its own thread and computer) and short-lived in-thread subagents.
- ChatGPT Plus or Pro sign-in for model access.
- Mobile: point the app at a self-hosted API origin, a native iOS inbox, and take control of the live desktop.
- Provider-neutral integrations: managed apps through Composio or Pipedream Connect, plus encrypted user-installed Treg, HTTPS MCP, and OpenAPI tool sources on web and mobile.
- Disconnect connected Composio plugins.
- Routines in plain language instead of raw cron.

### Removed

- Nonfunctional Grant folder picker in the desktop app.

### Messaging upgrade notes

- Webhooks use `/api/v1/messaging/webhook/<provider>`; the previous Sendblue path remains supported.
- Configure credentials for each messaging provider in `.env`; see [.env.example](.env.example).
- Unknown senders are ignored by default. `MESSAGING_OPEN_SIGNUP=true` restores automatic account
  creation from incoming messages and requires a deployment model key.
